# Side-Hustle Pattern Library

Use this reference when the user wants a side-hustle direction but has weak self-knowledge, little audience access, or unclear product form. It is a public-sample pattern library, not proof that any path will make money.

## Evidence Boundary

This library is based on public web samples and should only support lightweight hypothesis generation. It does not prove conversion rates, private-community retention, platform algorithm performance, or true profit.

Do not say "this will sell." Say "this is a pattern seen in public samples; validate with a small test."

## Pattern 1: Content First, Product Later

Use when:

- the user has expertise but no current audience
- the user is willing to publish but cannot use confidential cases directly
- the user's trust gap is larger than their product gap

Observed public signals:

- Creator/super-individual articles repeatedly frame content as a long-term acquisition asset, not just daily posting.
- A credible starting sequence is: specific problem -> useful content -> reusable artifact -> first feedback -> paid version.
- Free templates or free materials can become demand probes before a paid product.

Good first artifacts:

- 3-5 problem posts
- a teardown article
- a checklist
- a before/after explanation
- a free diagnostic table

Avoid:

- launching a paid course before showing judgment quality
- vague "I help people grow" positioning
- chasing broad trend words without a concrete audience problem

## Pattern 2: Template Pack /资料包

Use when:

- the user has reusable documents, SOPs, checklists, prompts, spreadsheets, or workflows
- the problem can be solved without 1:1 diagnosis
- confidentiality can be handled by anonymizing, generalizing, or rewriting as composite examples

Observed public signals:

- Public articles about virtual资料包 emphasize narrow pain points over large undifferentiated bundles.
- Digital goods often sell because delivery is instant, repeatable, and low marginal cost.
- Work-related examples include PPT templates, project management materials, SOP packs, prompt packs, and industry workflow guides.

Good first artifacts:

- "one-page checklist"
- "risk diagnosis table"
- "meeting review template"
- "prompt pack for a specific job"
- "workflow guide with examples"

Pricing signal:

- Public low-ticket examples often cluster around impulse-buy ranges such as 9.9-39.9 CNY for small materials.
- More specific professional templates can justify higher prices, but the skill should not assume pricing without platform research.

Avoid:

- selling a huge generic library
- using private company documents directly
- promising outcomes the template alone cannot deliver

## Pattern 3: Productized Diagnostic Service

Use when:

- the user's value depends on judgment, not just a downloadable artifact
- clients need help interpreting their own situation
- the user has limited time and needs a fixed-scope offer

Observed public signals:

- Productized consulting sources define the path as packaging expertise into repeatable, fixed-scope offers.
- Entry-level audits, assessments, or strategy sessions are often used as gateways to larger work.
- The value is not "one hour of time"; it is a clear before/after output.

Good first artifacts:

- 60-minute diagnosis with a fixed report
- asynchronous audit of a slide deck, project plan, or workflow
- "risk scan" with 5 findings and 3 next actions
- "second-opinion review" of an existing plan

Pricing signal:

- Public English consulting examples price audits much higher than Chinese solo side-hustle samples. Treat them as upper-bound B2B references, not a starting point for unknown creators.
- For a new side-hustler, validate interest before setting premium B2B prices.

Avoid:

- open-ended consulting
- custom implementation as the first offer
- requiring client data access before trust exists

## Pattern 4: Prompt Pack / Workflow Pack

Use when:

- the user's knowledge can be translated into repeatable AI prompts
- the target user already uses AI tools but lacks domain framing
- the output can be tested without private systems

Good first artifacts:

- prompt pack for one job-to-be-done
- "AI weekly report generator" prompt
- "risk review question bank"
- "meeting-to-action audit" workflow
- small demo using fake or sample data

Avoid:

- generic "1000 prompts" products with no domain context
- prompts that require data the buyer cannot provide
- pretending prompt packs replace domain expertise

## Pattern 5: Course / Mini-Course

Use when:

- the user can teach a repeatable process
- the buyer needs sequenced learning, not just a file
- the user can commit to updates, Q&A, or examples

Observed public signals:

- Knowledge-payment articles separate paid articles, paid Q&A, courses, training, and communities by difficulty and delivery burden.
- Courses tend to have higher perceived value than one-off Q&A, but require structure, examples, and sustained clarity.

Good first artifacts:

- 3-part mini-course
- 60-minute recorded workshop
- worksheet plus explanation video
- "case teardown + template" bundle

Avoid:

- training camps before there is proof of demand
- big promises around income or transformation
- turning every experience into a course

## Pattern 6: Paid Community / Knowledge Circle

Use when:

- the user already has a strong audience or repeated demand
- the topic requires continuous updates, peer support, or case discussion
- the user can sustain operations

Observed public signals:

- Public knowledge-community guides describe layered content: foundational knowledge, domain depth, and cross-domain connection.
- Communities carry higher ongoing delivery burden than templates or mini-products.

Good first artifacts before community:

- free newsletter or content series
- small template pack
- repeated Q&A sessions
- waitlist with clear promise

Avoid:

- starting a community before knowing what members repeatedly ask for
- low-price communities that still require high-touch service
- making the community the first validation step

## Pattern 7: Small Tool / Demo

Use when:

- the user can build or assemble a working prototype
- the target pain is repetitive and input-output based
- the tool can use public, sample, or user-provided data

Good first artifacts:

- spreadsheet calculator
- Notion/Airtable/Feishu template
- no-code prototype
- local demo with sample data
- report generator

Avoid:

- enterprise integrations as the first step
- SaaS subscriptions before distribution exists
- privacy-heavy workflows without trust

## Side-Hustle Fit Heuristic

Use this quick filter before recommending a path:

| Constraint | Better first step | Worse first step |
|---|---|---|
| Employed, 2-5 hours/week | content + template | custom consulting |
| No audience | public problem posts | paid community |
| Cases are confidential | composite teardown | raw case publication |
| Strong documents/templates |资料包 | coaching-only offer |
| Strong judgment but few assets | diagnostic service | generic template store |
| Strong technical build skill | small demo/tool | enterprise SaaS |
| High social resistance | written content, anonymous samples | daily face-on-camera video |
| Needs fast learning | interview/content test | full course |
