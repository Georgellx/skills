# Scoring Rubric

Use this rubric when converting multiple possible directions into recommended validation priorities.

## Score Scale

Use 1-5 for each dimension:

- 1 = weak or missing
- 2 = possible but vague
- 3 = plausible with some evidence
- 4 = strong and specific
- 5 = unusually strong

## Dimensions

| Dimension | Ask | Strong Signal |
|---|---|---|
| Self-fit | Can the user repeat this work without quickly burning out? | Energy, curiosity, relevant strength, tolerable tasks. |
| Evidence strength | Has the user actually solved this problem? | Completed cases, accepted work, artifacts, people helped. |
| Audience pain | Does a specific group urgently care? | Time/money loss, anxiety, deadline, visible struggle. |
| Audience access | Can the user observe or reach this group? | Existing network, community, platform, role proximity. |
| Differentiation | Why this user and not generic advice? | Unique stack, lived context, credible examples. |
| Validation cost | Can it be tested cheaply? | Posts, interviews, tiny offer, reusable template. |
| Ethical confidence | Is the promise honest and low-risk? | No exaggerated income claims; clear boundaries. |

## Interpretation

- **28+**: strong first validation candidate.
- **22-27**: plausible; narrow audience or strengthen proof.
- **16-21**: raw material; collect evidence before productizing.
- **15 or below**: keep as interest or long-term option, not current focus.

Do not use the total score mechanically. A low ethical-confidence score should block recommendation even if the total is high.

## Evidence Labels

Use labels in the final output:

- **A: validated**: strangers or real users showed commitment.
- **B: evidenced**: the user has solid personal/external proof, but market is not validated.
- **C: plausible**: coherent hypothesis with weak proof.
- **D: speculative**: interesting but not enough evidence.
- **E: not recommended now**: lacks fit, proof, access, or ethical confidence.

## Red Flags

- The target user is "everyone" or "ordinary people" with no painful scene.
- The offer is only "teach success" or "help make money."
- The user has no examples, no access, and no affordable way to test.
- The idea depends on copying a hot niche the user does not understand.
- The validation plan asks friends whether they like the idea instead of asking about past behavior.
- The user wants certainty before any contact with the market.

## Recommended First Tests

Choose one:

1. **Pain post test**: publish a post naming the painful scene and ask for comments or DMs.
2. **Checklist test**: create a one-page checklist and offer it to 5-10 relevant people.
3. **Interview test**: ask 5 people about their last real occurrence of the problem.
4. **Artifact audit**: review the user's existing notes/templates and identify reusable assets.
5. **Tiny paid offer**: only when there is enough proof; ask for a small real commitment.
