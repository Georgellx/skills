# Evidence-To-Offer Examples

Use this reference to turn a user's evidence into small, testable offers. It is designed for users who do not know what they can sell.

## Evidence Boundary

Do not treat evidence as automatic market demand. Evidence only tells you what the user may be able to do. Demand still needs validation through content, interviews, explicit requests, waitlists, or small payments.

## Conversion Ladder

Use this ladder:

```text
experience -> repeated problem -> capability -> proof -> market pain -> small offer -> validation action
```

If any step is missing, state what is missing.

## Evidence Type: Repeated Rescue Work

User signal:

- "People always ask me to save messy projects."
- "I get pulled in when nobody else can explain the situation."
- "I clean up broken processes."

Possible capability:

- diagnosing messy situations
- translating complexity into decisions
- creating order under ambiguity

Possible offers:

- "messy project diagnosis checklist"
- "one-hour rescue review"
- "project status truth table"
- "risk finding report"

Validation:

- publish 3 teardown posts about common failure patterns
- offer 3 free/low-cost audits in exchange for feedback

Warning:

- rescue work can become open-ended service. Define scope tightly.

## Evidence Type: Internal Reports / Executive Presentations

User signal:

- "I write reports for bosses."
- "I explain project value to leadership."
- "I turn scattered input into a presentation."

Possible capability:

- strategic framing
- executive-level communication
- value narrative

Possible offers:

- "executive report review"
- "PPT truth-check checklist"
- "digital transformation value narrative template"
- "leadership briefing structure"

Validation:

- anonymized before/after outline
- post: "why bosses dislike digital project reports"
- template: "one-page leadership update"

Warning:

- if the user lacks data access, do not offer full business diagnosis first.

## Evidence Type: Confidential Enterprise Cases

User signal:

- "I have cases but cannot publish them."
- "Materials involve commercial secrets."

Possible capability:

- case-based judgment, but public proof is constrained

Possible offers:

- composite case library
- anonymized pattern report
- "what went wrong" framework
- private diagnostic call

Validation:

- rewrite one case into a fictional composite
- remove company, role, money, and system-specific identifiers
- ask readers if the situation feels familiar

Warning:

- do not publish raw documents, screenshots, names, exact numbers, or client-specific workflows.

## Evidence Type: Templates / SOPs / Checklists

User signal:

- "I already have documents or workflows."
- "I repeat the same review steps."

Possible capability:

- codifying experience
- making tacit judgment visible

Possible offers:

- template pack
- SOP pack
- checklist bundle
- prompt pack that generates the first draft

Validation:

- release one free checklist
- ask users where they get stuck
- turn repeated questions into paid version

Warning:

- a template is not enough if users need expert interpretation.

## Evidence Type: People Ask For Advice

User signal:

- "Friends/colleagues ask me how to..."
- "Someone asked me to review..."

Possible capability:

- trusted judgment around a known problem

Possible offers:

- paid Q&A
- second-opinion review
- diagnostic mini-session
- curated resource list

Validation:

- ask the next 5 people what they tried before asking you
- convert their wording into content titles

Warning:

- one-off praise is not demand. Look for repeated asks.

## Evidence Type: Strong Tool Skill

User signal:

- "I can build automations, dashboards, prompts, or no-code tools."

Possible capability:

- turning workflows into small tools

Possible offers:

- micro-tool
- spreadsheet calculator
- no-code prototype
- "done-with-you setup"
- implementation guide

Validation:

- demo with sample data
- waitlist for setup help
- sell one manual version before automating

Warning:

- avoid building SaaS before proving repeated demand and distribution.

## Evidence Type: Hard-Won Mistakes

User signal:

- "I suffered through this."
- "I know where people get trapped."

Possible capability:

- risk prevention
- beginner mistake avoidance

Possible offers:

- "avoid these 10 mistakes" guide
- diagnostic questionnaire
- failure-pattern content series
- audit checklist

Validation:

- publish one mistake-per-post series
- track saves, shares, comments, and private questions

Warning:

- mistakes become valuable only when tied to a specific audience and cost.

## Offer Weight Class

Use this table to avoid overbuilding:

| Offer | Trust needed | Delivery burden | Best when |
|---|---:|---:|---|
| Problem post | Low | Low | no audience, no proof |
| Checklist | Low | Low | repeated problem is clear |
| Template pack | Medium | Low-Medium | reusable documents exist |
| Prompt/workflow pack | Medium | Low-Medium | user can codify AI-assisted steps |
| Paid article | Medium | Medium | user has writing clarity |
| One-hour diagnosis | Medium-High | Medium | judgment is core value |
| Mini-course | Medium-High | High | process is repeatable and teachable |
| Community | High | High | audience already repeats demand |
| Enterprise tool/SaaS | Very High | Very High | data access, sales, delivery, and support exist |

## Rejection Rules

Reject or postpone an offer when:

- it depends on private enterprise data the user cannot access
- it needs high trust before the user has public proof
- it turns into unlimited custom service
- it makes income or outcome promises
- it packages a desire rather than an evidenced capability
- it serves an audience the user cannot reach or observe

## Example Mappings

### B2B Product Manager With Confidential Enterprise Cases

Evidence:

- wrote executive reports
- managed messy digital projects
- saw project delays, user resistance, and value narrative gaps

Tempting direction:

- enterprise boss digital twin / management-risk SaaS

Why risky as first step:

- requires data integration, trust, procurement, and delivery team

Smaller entry:

- content series: "老板怎么看数字化项目风险"
- checklist: "项目汇报真实性校验清单"
- template: "项目进度/成本/风险一页表"
- diagnostic: anonymized report review

### Teacher With Many Classroom Cases

Evidence:

- repeated parent communication
- classroom observation records
- course-story materials

Tempting direction:

- full education consulting brand

Smaller entry:

- article series with classroom observation patterns
- parent communication script pack
- lesson reflection template

### Operations Person With SOP Experience

Evidence:

- wrote SOPs
- trained colleagues
- improved recurring workflows

Tempting direction:

- generic operations course

Smaller entry:

- one SOP template for a specific process
- before/after SOP teardown
- paid SOP review session
